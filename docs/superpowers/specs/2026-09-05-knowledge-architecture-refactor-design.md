# cli-novel-writer 知识架构重构设计

日期：2026-09-05
状态：已获用户分节确认

## 背景与目标

当前 `cli-novel-writer` skill 是一个「多核协同写作」skill：主会话为统筹队长，通过 Agent 工具派发 5 个专职子代理（世界/剧情/人物/文笔/复核）。其核心长板是**强状态追踪**（白皮书/人物档案/伏笔台账/章节版本）与**真并行上下文**（子代理独立上下文、数据靠文件传）。

问题：所有子代理规则、写作约束、审查原则全部堆在单个 SKILL.md（11KB）里，单文件过长会"变钝"。对照参考项目 `Chinese-WebNovel-Skill`（主文件路由 + 专项模块下沉 + 本地语料检索），借鉴其**知识组织方式**来重构我们的知识架构，同时**保留我们的多代理协同**。

本次落地 4 件事：

1. SKILL.md 瘦身 + 子代理规则下沉成模块
2. 去 AI 味 系统化
3. 复核子代理升级为"六一致性清单 + 正反例"
4. 语料例库（借隔壁精选摘录）

## 架构总览

```
cli-novel-writer/
├── SKILL.md                        # 瘦身：定位 + 派单协议 + 三件事编排 + 子代理入口
├── README.md                       # 同步更新架构说明
├── references/
│   └── agents/                     # 5 个子代理，每个一个模块目录
│       ├── 文笔/   rules.md + good_examples.md + bad_examples.md + checklist.md
│       ├── 剧情/   rules.md + checklist.md
│       ├── 人物/   rules.md + checklist.md
│       ├── 世界/   rules.md + checklist.md
│       └── 复核/   rules.md + good_examples.md + bad_examples.md + checklist.md
└── scripts/
    ├── count_cjk.py                # 已有，不动
    └── search_examples.py          # 可选：轻量检索脚本（本次先不写，见 §5）
```

## §1 SKILL.md 瘦身 + 子代理规则下沉

### 现状

- SKILL.md:35-45 五岗位长模板（文笔/复核/世界/剧情/人物）全部内联，是文件膨胀的主因。
- 派单协议（SKILL.md:22-33）要求派单时复制对应岗位全文，导致每次派单 prompt 很长。

### 改动

**新建 `references/agents/<角色>/` 目录**，每个子代理统一骨架：

- `rules.md`：角色规则全文（从 SKILL.md 原样下沉，可补充分层诊断细节）。
- `checklist.md`：该子代理落笔/判决前必查清单。
- `good_examples.md` / `bad_examples.md`：正反例（文笔、复核必建；剧情/人物/世界本期可只建 rules + checklist，后续补例库）。

**SKILL.md 瘦身**：

- 保留：定位、多核协同说明、派单协议（改为"发要点 + 模块路径"）、全局铁律（通信经济/否决权/熔断权）、工作流（逐章循环/全局刷新）、本地存储规范、章节版本管理、启动流程、输出纪律、脚本工具。
- 移除：五岗位长模板正文，改为**每个子代理一个入口链接**（指向 `references/agents/<角色>/rules.md`），并附一句话职责摘要。
- 新增：§2 去 AI 味、§3 复核六一致性，作为全局原则提到主文件（或放复核 checklist，主文件只留一句话引用）。

**派单协议改动（已确认：折中——发要点 + 路径）**：

每次派单 prompt 三块不变（角色规则/本次任务/数据来源），但第 1 块改为：

```
角色：文笔子代理。完整规则见 references/agents/文笔/rules.md，落笔前先读它的
  checklist.md 并回答 5 句（§2）。本次任务是：……
```

即：发角色要点 + 模块路径，子代理按需深读，不再塞全文。铁律不变（数据靠文件传、一次只派一件事、写正文只派文笔）。

## §2 去 AI 味 系统化

### 现状

文笔子代理只有一句「不炫技、不堆辞藻」，无分层诊断；复核黄灯只说「文笔略水」。

### 改动

**文笔 `checklist.md` 落笔前必答 5 句**：

1. 这一拍最重要的局面变化是什么？
2. 我准备用哪个动作或物件把它立住？
3. 这一拍里谁最有压、谁最弱？
4. 哪一句对白必须带身份感？
5. 这一段最该避免哪一句空泛总结？

**分层诊断（写后自查，四层）**：

- 空泛总结层：「她很难过」「气氛很微妙」→ 改动作化 / 物件化 / 反应链。
- 人物声音同质层：所有人工整讲理 → 拉身份差 / 立场差 / 压人方式差。
- 套话氛围层：「空气仿佛凝固」→ 改场内变化 / 可听见的小声音 / 距离与动作变化。
- 平均节奏层：句子一样长 → 拉句长 / 动作截断 / 短句插刀。

**复核 `checklist.md` 增项**：把「文笔略水」黄灯展开为四层逐项排查，判决理由必须落到具体层。

**关键点**：去 AI 味不是最后润色，而是从构思就约束——故落在「落笔前 5 句」，不是交稿后修补。

## §3 复核子代理升级为「六一致性清单 + 正反例」

### 现状

复核子代理靠三色灯 + 主观判断，缺固定检查项，易"拍脑袋"。

### 改动

**六类一致性（进复核 `checklist.md`，逐项判 🔴/🟡/🟢）**：

1. 剧情逻辑一致性：关键事件有没有前提？关键决定有没有触发？关键变化有没有后果？
2. 人物目标一致性：主角这章想做什么？过程里有没有无故漂移？
3. 情绪与关系一致性：情绪有没有来路？关系温度跟上一场对不对得上？
4. 身体与信息状态一致性：伤势、疲劳、秘密、误会、已知信息有没有丢？
5. 场景与转场一致性：读者会不会迷路？上一场余力有没有带到下一场？
6. 章末承接一致性：章末收在变化上没？下一章第一拍能不能接住？

**用法**：复核逐项过 6 类，判决理由必须落到具体某一类，而不是"感觉不对"。任两项不稳即整体不过关，回对应模块修（剧情逻辑→剧情子代理、人物目标→人物子代理、身体信息→伏笔台账/人物档案、转场/章末→文笔重写）。

**bad_examples**：典型反例（讲完题、收总结、关系温度断、空气凝固等），帮复核识别"为什么不合"。

三色灯保留为结论层；判决过程改用六一致性。

## §4 语料例库（借隔壁精选摘录）

### 现状

本项目无任何语料/正反例库，文笔纯靠模型内存。

### 改动

不建独立 `data/` 大语料库，只在 `references/agents/文笔/` 内建**精选例库**：

- `good_examples.md`：从隔壁 `Chinese-WebNovel-Skill/analysis/excerpts.csv` 按 `excerpt_type`（开头钩子/高张力对白/结尾余韵）精选 2-4 组，按「该学什么」重组，只借结构不借句面。
- `bad_examples.md`：手写典型反例（不用隔壁的），含 §2/§3 的反面。

**复核 `bad_examples.md`**：手写六一致性反例。

**不写检索脚本（本期）**：文笔派单时直接读 `good_examples.md` 即可，不需要脚本。若后续需要"先检索再写"再单独升级。

### 为什么这样取舍

- 我们的架构是「子代理读模块」，不是主会话检索全语料。
- 保持仓库小、专注，不引入隔壁 12M 体重。
- 文笔真正需要的是「落笔前有几个近似开头/对白/章末」，不是全网语料。

## §5 边界与不做的事

- 不改多代理架构（不引入检索路由、不做主会话语料检索）。
- 不改 `scripts/count_cjk.py` 及测试。
- 不建独立 `data/` 目录、不写 `search_examples.py`（本期）。
- 剧情/人物/世界本期只建 `rules.md + checklist.md`，例库后续补。

## 测试与验证

- `count_cjk.py` 及 pytest 不受影响（无代码改动）。
- 验证方式：结构落盘后，用一个虚构派单 prompt 演练文笔子代理，检查它能否按 checklist 走完 5 句 + 分层自查。
- 语法/路径校验：确保 SKILL.md 内链接可点（相对路径正确）。

## 维护原则（沿用）

- 不把细节再塞回主 SKILL.md。
- 新问题优先拆模块 / 补例库，不扩总 prompt。
- 模型先匹配素材，再构思，再写作。
- 每章写完默认走复核的六一致性。
