# cli-novel-writer 续写 / 外来小说导入设计

日期：2026-09-06
状态：已获用户确认

## 背景与目标

当前 skill 的启动流程（`SKILL.md` 启动流程）只能处理两种情形：

- **新开项目**：用户给题材/梗概 → 世界+剧情联席出草案 → 人物出档案 → 写第一章。
- **继续 skill 项目**（`SKILL.md` 「项目索引与续写回查」）：cwd 找 `项目索引.md` → 以其绝对根路径续写，或用户指定路径下已有索引则复用。

**缺口**：对于「其他来源的小说」——只有小说本体、各个章节、没有 skill 结构化文件（无 `项目索引.md`/`叙事宪法.md`/`世界规则白皮书.md`/`人物档案.json`/`伏笔台账.md`/`章节目录.md`）——skill 目前没有任何规则去读取并接入续写。用户无法对这类项目续写。

本次落地：**让 skill 支持对外来小说（原始章节）的导入与续写**。启动流程改为三路分流（新开 / 继续 skill 项目 / 导入外来项目）。导入路径下，队长派子代理读完外来章节，推导生成结构化文件（标注「从原章节推导」），向用户确认草案后再续写。

## 已确认的设计决策

1. **保留原章节 + 叠加结构文件**：外来小说的原始章节文件**只读、不复制、不改写**；在项目根旁生成结构化文件，并记录章节顺序映射（原文件名 ↔ 章节号）。
2. **需用户确认草案**：子代理读完全章生成 叙事宪法/世界规则/人物档案/章节目录/伏笔台账 草案 → 向用户展示要点 → 用户确认/修正 → 定稿 → 续写。
3. **第零步分流三路**：新开 / 继续 skill 项目 / 导入外来项目，并入同一个启动流程分流。
4. **推导标记 + 宽松复核**：导入生成的结构文件标注「从原章节推导」；续写复核对导入的设定/人物/伏笔**宽松**（不强求与 skill 原生项目一致），但对续写**新增**内容严格一致。

## 架构总览

```
启动流程（第零步改为三路分流）
├─ A 新开项目        用户给题材/梗概 → 现状流程（世界+剧情联席 → 人物 → 写第一章许可）
├─ B 继续 skill 项目  已有 项目索引.md → 现状流程（回查 → 读章节目录最高版本续写）
└─ C 导入外来项目     只有原始章节、无结构化文件
     ① 定位来源（目录/文件列表）→ 确认章节顺序
     ② 派 剧情/世界/人物 子代理读完全章，产出草案：
       叙事宪法.md / 世界规则白皮书.md / 人物档案.json / 章节目录.md / 伏笔台账.md
       全部标注「从原章节推导」
     ③ 向用户展示要点 → 确认/修正 → 定稿
     ④ 建 项目索引.md（含「外来导入」来源标记 + 章节映射表）
     ⑤ 续写：从最后一章的最高顺序，按 A 的逐章流程继续
```

### 项目目录结构（项目根 = 解析出的目录，外来导入时）

```
├─ 项目索引.md            元数据：项目名 / 创建日期 / 项目根（绝对）/ 来源标记（外来导入）/ 章节映射表
├─ 叙事宪法.md            核心冲突、禁用项、硬性约束【外来导入：从原章节推导】
├─ 世界规则白皮书.md      物理法则、地理、货币、种族、战力天花板与差值【外来导入：从原章节推导】
├─ 人物档案.json          按 Schema 存每个角色【外来导入：从原章节推导】
├─ 伏笔台账.md            伏笔埋设/回收状态表【外来导入：从原章节推导】
├─ 章节目录.md            每章最新版本 + 一句话梗概【外来导入：含原文件名映射 + 章节顺序】
└─ 第N章-vX.md            续写产出的新章节正文（带版本号）
```

## §1 启动流程：第零步三路分流

用户给题材/梗概、或说「开始 / 续写 / 继续」后，按以下分流判定，每步完成后先向用户汇报、等确认再继续：

1. **判定输入**：
   - 用户给了题材/梗概（未提已有小说）→ **A 新开项目**。
   - 用户说「续写 / 继续」或给的项目目录下**已有 `项目索引.md`** → **B 继续 skill 项目**（回查规则见 §2，沿用现状）。
   - 用户给的目录下**只有原始章节 / 正文、无结构化文件**（无 `项目索引.md` 等）→ **C 导入外来项目**。
2. **分流后各自执行**：
   - **A**：沿用现状第零步 → 三步走（世界+剧情联席 → 人物 → 写第一章许可）。
   - **B**：沿用现状回查规则（§2）。
   - **C**：见 §3 导入流程。

> 分流判定只看「项目目录下是否已有 skill 结构化文件」；只要目录下存在 `项目索引.md` 即走 B，否则按是否有原始章节走 C 或 A。

## §2 继续 skill 项目（沿用现状，补来源标记说明）

回查规则（用户说「继续上次小说 / 续写」时）：
1. 先在 **cwd** 找 `项目索引.md`；找到 → 以其 `项目根目录` 为项目根。
2. 找不到 → 问用户「上次项目目录在哪？」，用户给指即用。
3. 若用户指定了新路径且该路径下已有 `项目索引.md` → 直接重用该索引继续。

`项目索引.md` 中若标记为「外来导入」，则该项目按 §4 的宽松复核规则处理（对导入设定宽松、对续写新增严格）。

## §3 导入外来项目流程（第零步 C 路）

队长进入导入流程，每步先向用户汇报、等确认再继续：

1. **定位来源 + 确认章节顺序**：读取外来目录/文件列表，按文件名序号排序确认章节顺序；若无法确定顺序（无序号/混杂）→ 停住问用户。
2. **派子代理读全章、出草案**：派 剧情/世界/人物 三个子代理读完外来全部章节，各自产出对应草案：
   - 世界 → `世界规则白皮书.md`（含战力天花板与差值）
   - 剧情 → `叙事宪法.md` + `伏笔台账.md` + `章节目录.md`（含原文件名 ↔ 章节顺序映射）
   - 人物 → `人物档案.json`（按既有 Schema）
   - 所有草案文件头部标注「从原章节推导」。
3. **用户确认草案**：向用户展示各草案要点 → 用户确认/修正 → 定稿。草案被推翻则重新派对应子代理修订，不硬压。
4. **建 `项目索引.md`**：记录项目名、创建日期、绝对根路径、**来源标记「外来导入」**、以及**章节映射表**（原文件名 ↔ 章节号 ↔ 状态）。
5. **续写**：从最后一章的最高顺序，按 A 的逐章流程继续（派文笔写下一章 → 复核 → 下一章）。

> 外来原文件**只读**：不复制、不改写、不入版本管理。续写产出的新章节写入项目根下 `第N章-vX.md`。

## §4 复核：外来导入宽松规则

复核子代理在复核外来导入项目时：
- 对「从原章节推导」的设定/人物/伏笔（宪法、白皮书、人物档案、伏笔台账）**宽松**：不强求与 skill 原生项目一致，不因导入期推导偏差误判。
- 对续写**新增**内容**严格**一致：新章节必须与已定稿的导入设定一致，六一致性照常适用。

> 此规则写入 `references/agents/复核/rules.md`，与原生项目（严格一致）区分。

## §6 边界与不做的事

- **不做外来章节的改写/复制**：原始文件只读；结构化文件是叠加生成，不替换原章节。
- **不做多项目并行管理**：一次会话只管一个项目。
- **不改 `scripts/count_cjk.py` 及测试**：路径解析/导入流程在 skill 文本（模型执行）层。
- **不新增脚本**：导入流程全部由队长文本执行 + 子代理。
- **不保证外来章节自动编号正确**：顺序无法确定时停住问用户，不硬猜。

## §7 测试与验证

- 纯文本/模型层变更，无 Python 测试。
- 验证方式（手动演练）：
  1. 外来章节目录（无结构化文件）→ 分流判定进 C → 派子代理读章 → 出草案 → 展示确认 → 建 `项目索引.md`（含来源标记 + 映射）→ 续写。
  2. cwd 有 `项目索引.md` → 分流判定进 B → 按现状回查续写。
  3. 新题材 → 分流判定进 A → 现状三步走。
- 语法/路径校验：确认 SKILL.md / README.md / CLAUDE.md / 复核 rules 内的链接与新规则可解析。
